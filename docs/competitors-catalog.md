**Описание (как подано авторами):**

> SAUTI AI is a Voice-to-Action Community Intelligence Platform designed to make community reporting simple, accessible, and inclusive. Instead of filling out complicated forms or typing long messages, users can simply speak about a problem they are experiencing or witnessing. Powered by AssemblyAI's Voice Agent technology, SAUTI AI listens to users in real time, understands their concerns, and engages them in a natural conversation. The AI asks intelligent follow-up questions to gather important details such as the type of issue, location, severity, and description. Once enough information has been collected, SAUTI automatically converts the conversation into a structured incident report. It generates a unique reference number and sends the report to a community management dashboard, where organizations can track, manage, and respond to reported issues. For example, a user can say, "There is a broken water pipe outside Kisii University." SAUTI can ask whether flooding is occurring, determine the urgency, capture the location, and submit the issue automatically. SAUTI AI demonstrates a powerful new approach to digital public services: Speak → Understand → Decide → Take Action. The platform can support communities, county governments, universities, NGOs, and property managers by making issue reporting faster and more accessible. In the future, SAUTI can expand into agriculture, health navigation, and other essential services, becoming a universal voice interface for underserved communities across Kenya and Africa.

## The problem

Everyone tells candidates to "practice out loud" — nobody can sit with them at
11 pm before the big day. Reading questions silently doesn't train the part that
fails in real interviews: **speaking coherently under pressure**.

## What MockMate does

1. **You speak, it interviews.** A fully hands-free voice conversation — the
   interviewer picks up when you stop talking (semantic turn-taking), never
   cuts you off mid-thought, and you can interrupt it like a real human.
2. **Every answer is scored live.** The interviewer calls client-side tools
   (`log_question`, `score_answer`) that stream structured evaluations into the
   on-screen HUD — per-question 1–10, strengths, improvements.
3. **Delivery analytics.** Filler words ("um", "like", "you know"), words-per-minute

That is why voice agents in banking are still mostly read-only: they will tell you your balance, but they will not move your money. The usual answer is to push accuracy higher. Accuracy is an asymptote: it never reaches a point where executing an irreversible action on a guess is acceptable. Voice Action Gate changes what the failure does, not how often it happens. The two directions are not symmetric — a wrong block costs the user a repeated sentence, a wrong pass moves real money — so the system is not built symmetric. The mechanism is a capability, not a check. Code that performs an irreversible action accepts only an Execute credential, and that credential has exactly one construction site: the gate. It is minted only when every argument of the proposed action is grounded in a witness drawn from AssemblyAI's word-level transcript. 'I could not tell' is a refusal, never a pass: in this shape there is no expression you could write that would turn it into one. Two details carry the weight. First, the witness set is generated from the transcript alone, before the proposal is visible — otherwise a model that invents a number gets to pick the search query, and an unrelated number becomes its evidence. Second, the normalizer that turns 'five hundred' into 500 is deliberately a partial function: it may answer UNDECODABLE, and UNDECODABLE is not a pass. A normalizer with a fallback return value quietly converts 'I cannot read this' into 'I believe it equals something' — the direction that costs money. Stack: AssemblyAI streaming speech-to-text — audio goes browser-to-AssemblyAI directly, so the Worker only ever sees words. A dependency-free Python gate, pinned by a mutation arm that turns red if that separation is undone. Cloudflare Workers, with the daily token cap in a Durable Object, not KV.

> In Latin America, WhatsApp is not a channel — it is the channel. Customers message small businesses there, usually with a voice note. RevenueFlow answers instead. It transcribes the voice note with AssemblyAI Universal-3.5 Pro, extracts intent through the AssemblyAI LLM Gateway, resolves "el jueves en la tarde" into a real timestamp in the business's timezone, checks actual availability, books the appointment, and replies — in about seven seconds. Language is detected, not assumed. Detection runs with expected_languages, a country fallback and code_switching for mixed voice notes, and on_low_language_confidence set to fallback, so a noisy note degrades to the country's language instead of failing outright. It answers in Spanish, Portuguese or English — and still books for someone writing in Russian or Mandarin. One rule shapes everything: the model decides what the customer wants; the system decides what is allowed. The model cannot invent a service (catalog IDs only), a date (it returns a weekday symbol and the system computes the date), or availability. Replies are hand-written templates, because they carry exact dates and times, and a hallucination there is a lost appointment in real life. It holds the conversation too. Four words — "mejor para el viernes" — reschedule the right appointment to Friday at the same hour, without repeating the service or the date. Complaints, money and medical questions stop and go to a human. Running on a real WhatsApp number, in two countries, with row-level tenant isolation and money stored as integer minor units with its FX rate. 177 tests. Source public under MIT.

# Clinic Scheduling Voice Agent

A real-time voice agent that calls a patient to schedule a clinic appointment, negotiates an available time slot, confirms it explicitly, and books it — built on AssemblyAI's Voice Agent API.

Built for the [AssemblyAI Voice Agent Hackathon](https://lablab.ai) (Sep 2026).

## What it does

The agent places a phone-style conversation with a patient:

1. Greets the patient and confirms identity
2. Asks for a preferred day/time
3. Calls a scheduling tool to find real available slots
4. Negotiates until the patient picks a slot they like
5. Repeats the full date, time, and clinic name back for confirmation
6. Books the appointment only after an explicit "yes"
7. Confirms the final booking and ends the call politely

The agent never claims a slot is booked until the backend confirms it, and gracefully retries or offers alternatives if something goes wrong — you can see this resilience in the demo video, where the agent politely retries a failed booking attempt before succeeding.

## Architecture

- **Voice layer**: AssemblyAI Voice Agent API (speech-to-text, LLM reasoning, and text-to-speech in a single WebSocket connection)
- **Scheduling backend**: A small FastAPI service (`scheduling_backend.py`) with two endpoints:
  - `find-available-slots` — returns open appointment slots, filtered by date/time-of-day and converted to the patient's timezone
  - `book-appointment` — reserves a slot transactionally (SQLite `BEGIN IMMEDIATE`), so two callers can never double-book the same slot
- **Agent config**: `clinic_agent.py` creates/updates the AssemblyAI agent via their REST API, wiring the two backend endpoints in as HTTP tools the agent can call mid-conversation

The backend is deployed publicly on Google Cloud Run so AssemblyAI's servers can reach it during a live call.

## Why this matters

Clinics and small practices lose real time and money to phone-tag scheduling.
