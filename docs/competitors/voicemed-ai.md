**1. Что построено**

Голосовая медсестра-триажист «Aria»: пациент говорит, она ведёт структурированное клиническое интервью (жалоба → симптомы → медикаменты → красные флаги → ESI → SOAP → запись на приём), оценивает срочность по Emergency Severity Index 1–5, проверяет опасные лекарственные взаимодействия, срабатывает экстренной эскалацией на красные флаги и выдаёт готовую для EMR SOAP-заметку с ICD-10 кодами, скачиваемую как Markdown. Работает на английском и испанском. Есть клинический дашборд с живым транскриптом, степпером интервью, ESI-датчиком, таймлайном вызовов инструментов и режимом «Demo Copilot» для презентации.

**2. Как использован AssemblyAI**

Это **самое глубокое и самое точное использование AssemblyAI среди разобранных**, и по этому критерию проект — эталон:

- **Voice Agent API** как единственный рантайм диалога: «STT + LLM + TTS over a single WebSocket, server-side tool calling, semantic turn detection & barge-in». Эндпоинт назван буквально: `wss://agents.assemblyai.com/v1/ws`.
- **Модель**: Universal (в диаграмме «Speech-to-Text (Universal)»). Единственное место, где конкретика слабее конкурентов — точная версия (3 / 3.5 / Pro) не указана.
- **TTS-голоса названы по именам**: `alba` (английский) и `lola` (испанский, «native Spanish voice»).
- **Аудиоформат точный**: 24 kHz PCM16, base64 в `reply.audio`, захват через AudioWorklet с ресемплингом **внутри ворклета**, воспроизведение через ring buffer.
- **Протокольные события перечислены по именам**: `session.accepted`, `session.update`, `session.ready`, `session.end`/`session.ended`, `reply.audio`, `reply.done`, `transcript.agent`, `input.speech.started`, `tool.call`, `tool.result`, `status: "interrupted"`. Такой уровень детализации бывает только у человека, который реально отлаживал этот WebSocket.
- **Spec-exact tool loop**: результаты `tool.call` **ставятся в очередь и сбрасываются только когда `reply.done` — последнее событие**, и **отбрасываются при `status:"interrupted"`** — «exactly per the client-side-tools contract, which keeps turn-taking unbroken». Это самая тонкая деталь всего сравнения: они поняли, почему наивная отправка tool-результата ломает turn-taking.
- **`execution_mode: "hold"`** для `emergency_alert`, чтобы во время критической эскалации звонящий оставался с Aria.
- **Barge-in, который действительно работает**: `input.speech.started` сбрасывает ring buffer воспроизведения посередине фрейма (без устаревшего аудио), а ворклет захвата никогда не роутится на колонки (нет эхо-петли). Плюс браузерный AEC.
- **Смещение распознавания под медицинскую речь**: `keyterms` + `transcription_prompt` под названия препаратов и клиническую лексику; для испанского keyterms заданы явно (*dolor en el pecho*, *warfarina*, *cara caída*). `interrupt_response: true`.
- **Безопасность ключа и биллинга**: API-ключ не покидает сервер — `GET /token` выдаёт одноразовые токены с **2-минутным окном погашения**, сессии ограничены **30 минутами**; страница подключается с `?token=…`, конфиг берёт из `GET /session-config?lang=en|es`.
- **Чистое закрытие сессий**: каждый путь (кнопка Stop, закрытие страницы, shutdown сервера) отправляет `session.end` и **ждёт `session.ended`** — «no 30-second billable grace windows». Мысль о счёте за неаккуратно закрытые сессии — признак человека, который платил за этот API.
- **Два режима агента**: inline (`GET /session-config?lang=es` строит сессию из `agents/voicemed_triage_es.jsonc`) и stored-agent (`python publish_agent.py --lang es` → `POST/PUT /v1/agents`, сохраняет `AGENT_ID_ES` в `.env`), причём stored-agent открывает путь на телефонию (Twilio). Оба пути работают, JSONC — «single source of truth».

Шесть инструментов, все исполняются на сервере против локальных JSON: `symptom_lookup` (`data/symptoms.json`, **20 симптомов**), `drug_interaction_check` (`data/drug_interactions.json`, **20 пар, alias-normalized**), `triage_assessment` (`app/tools/triage_assessment.py`), `generate_soap_note` (`data/icd10_codes.json`), `book_appointment` (mock-календарь провайдера), `emergency_alert` (`app/tools/emergency_alert.py`).

**3. Архитектура и стек**

Python 3.10+, FastAPI 0.115.0, uvicorn 0.30.0, websockets>=14.0, aiohttp 3.10.0, jinja2 3.1.4, aiofiles 24.1.0, **aiosqlite 0.20.0** для истории сессий и живой статистики, pytest 8.3.3. Фронт — ванильный JS + Web Audio API/AudioWorklets, без фреймворка (`static/index.html`, `style.css`, `app.js`, `audio-processor.js`). Деплой: Render через `render.yaml` Blueprint, с осознанным обоснованием выбора против Vercel: always-on процесс без cold start, поддержка WebSocket для `/ws`-моста, опция persistent disk с `VOICEMED_DB_PATH=/data/voicemed.db`, чтобы история переживала редеплой.

Поток аудио нарисован ASCII-диаграммой с тремя колонками (браузер / FastAPI-мост / AssemblyAI) и подписанными направлениями. Ключевая архитектурная честность: **вся тяжёлая часть (STT, LLM, TTS, turn detection) — на стороне AssemblyAI**, а FastAPI — мост, который исполняет клинические инструменты и проксирует аудио. Структура файлов в README расписана полностью, с назначением каждого модуля (`app/voice_agent.py` — клиент Voice Agent API с очередью инструментов и barge-in; `app/agent_config.py` — JSONC-парсер и конвертер в inline-сессию).

**4. Настоящая инженерная суть**

- **Спек-точный tool-queue/flush с отбрасыванием по `interrupted`** — реально сложная часть. Ошибка здесь проявляется как «агент заикается / перебивает сам себя / теряет ход», и большинство участников её даже не заметят.
- **Barge-in без эхо-петли**: сброс ring buffer посередине фрейма + изоляция ворклета захвата от выхода. Работа на уровне Web Audio, не копипаста.
- **Детерминированный скоринг срочности**: «the final urgency score is decided by deterministic local code — not the LLM». Тот же правильный инвариант, что у RevenueFlow и Veritas, но применённый к самому опасному решению системы.
- **Билингвальность без дублирования логики**: инструменты сохраняют английские имена и имена аргументов, поэтому один серверный диспетчер и одна база знаний обслуживают оба языка; меняются только промпт, голос и keyterms. Это правильное разделение, а не копия агента.
- **Дисциплина жизненного цикла сессии** (гарантированный `session.end` + ожидание `session.ended`) и **одноразовые токены** вместо ключа в браузере — вещи, которые отличают прототип от того, что можно показать платящему клиенту.
- **`scripts/check_ids.py`** — проверка, что каждый DOM-id, на который ссылается `app.js`, существует в `index.html`. Нестандартный, умный тест против целого класса тихих поломок фронта.
- **Обязательность красных флагов в интервью**: вопросы про боль в груди, признаки инсульта (FAST), кровотечение, анафилаксию и суицидальные мысли — не опциональная ветка, а обязательная часть протокола.

Обёрткой является предметная база: 20 симптомов и 20 пар лекарственных взаимодействий в JSON — это демо-масштаб, и авторы это не скрывают. ESI-скоринг и SOAP-шаблон — собственный код, но простой.

**5. Метрики и доказательства**

Лучшая доказательная база среди разобранных, и единственная, где числа что-то значат:

- **44 автоматических теста pytest**, `python -m pytest tests -q`, с указанием покрытия: «config schema, tools, protocol loop (mocked WS)». Тестируется именно протокольный цикл на мок-WebSocket — то есть проверяется та самая сложная часть.
- **`smoke_test.py` — живая проверка против реального API**, с приведённым в README выводом записанного прогона и **таймингами по шагам**:
  - `1. mint browser token (GET /v1/token)` — **0.97 s**
  - `2. open WebSocket (wss://agents.assemblyai.com/v1/ws)` — **0.95 s**
  - `3. send inline session.update (prompt + 6 tools)` — **8129 bytes**
  - `4. session.ready` — **0.57 s**
  - `5. greeting reply (reply.audio + transcript.agent)` — **5.63 s, 269280 bytes PCM**
  - `6. session.end -> session.ended` — **0.26 s**
  - `7. stored-agent binding (session.update {agent_id})` — **2.13 s**
  - `PROTOCOL VERIFIED END-TO-END ✔`
- Шаг 7 валидирует именно тот путь привязки stored agent, который использует работающее приложение; без `AGENT_ID` шаг печатает SKIP, и оба пути работают. Это грамотно продуманный тест, а не декорация.
- Дополнительные проверки: `node --check static/app.js && node --check static/audio-processor.js` (синтаксис JS), `python scripts/check_ids.py`.
- Есть **живой чип латентности speech→reply прямо в UI** — измерение видно судье в реальном времени.
- **Честность про Render free plan**: «сервис засыпает через ~15 минут без трафика, первый запрос потом занимает ~30–60 с», с советом держать таб открытым или пинговать `/api/health`. Автор сам предупреждает о проблеме, которая может испортить его же демо.

Критика доказательств: **5.63 s на приветственный ответ — это медленно**, и это единственная реально измеренная латентность голосового цикла в проекте. Она относится к старту сессии, но других чисел нет: **нет измерения turn-to-turn латентности в устоявшемся диалоге**, нет p50/p95, нет точности распознавания медицинской лексики (WER), нет валидации ESI-скоринга против клинического golden set. Заявленные «dangerous drug interactions» проверяются на 20 парах — покрытие тривиально, а точность детекции не измерена.

**6. Сильные стороны**

- **Application of Technology — первое место среди разобранных, безоговорочно.** Единственный проект, который использует Voice Agent API целиком и правильно: tool calling, semantic turn detection, barge-in, TTS, stored agents, keyterms, token minting, дисциплина закрытия сессий. Судья из AssemblyAI, читая раздел про очередь tool-результатов и `reply.done`, узнает свою собственную документацию — и то, что участник её понял.
- **Доказуемость**: 44 теста + живой smoke-test с приведёнными таймингами и «PROTOCOL VERIFIED END-TO-END». Никто среди разобранныхблизко не подошёл.
- **Presentation**: 60-секундный демо-скрипт с построчным «скажи это → увидишь это» (4 шага, от «crushing chest pain» до SOAP-заметки), встроенный **Demo Copilot** (`Alt+D`), который показывает следующую реплику и автоматически продвигается, когда Aria услышала, плюс «Skip» для шумной комнаты. Это решает главную боль голосового демо на сцене. Плюс прогресс-степпер, ESI-датчик с цветовой шкалой, таймлайн инструментов с аргументами и ✓/✗, пульсирующий красный баннер.
- **Доступность как обоснование голоса, а не украшение**: «triage works for elderly, low-vision, low-literacy, and hands-busy users who fail at forms and menus». Лучший ответ на вопрос «почему вообще голос» среди разобранных.
- **Билингвальность** (en/es) с нативным испанским голосом — реальное расширение аудитории, не галочка.
- **Зрелая рамка безопасности**: «Never diagnoses», запрет советов по дозировкам в системном промпте, обязательные вопросы о красных флагах, эскалация с явным «call 911 / 988», детерминированный финальный скоринг, дисклеймер «not a medical device» **дважды** (в разделе безопасности и в подвале), аудио не сохраняется, SQLite хранит только транскрипты и метаданные.
- Доступность UI на уровне CSS: `:focus-visible`, `prefers-reduced-motion`, адаптивность до ширины телефона.

**7. Слабые места и уязвимости**

- **12 коммитов** — худшая история работы среди разобранныхвместе с Veritas. При 44 тестах и глубоком протокольном коде это означает крупные заливки; судья, который смотрит на историю как на доказательство собственной работы, её не увидит.
- **5.63 s до приветствия** — единственное измеренное число латентности, и оно плохое. Если в демо это повторится, «real-time» питч пострадает. **Turn-to-turn латентность не измерена вообще**, и это подозрительно для проекта, который в остальном так тщательно измеряет: похоже, измерили то, что выглядит прилично, и не измерили то, что могло выглядеть хуже.
- **Предметная база игрушечная**: 20 симптомов, 20 пар взаимодействий, mock-календарь. Для триажа реального пациента это на три порядка меньше нужного. Судья спросит «что происходит на 21-м симптоме» — и ответ будет «ничего».
- **Медицинская ответственность остаётся**, несмотря на дисклеймеры. Система говорит пациенту с болью в груди «звоните 911» — это правильно; но она же может **не сработать** на симптом, которого нет в 20 записях, и тогда пациент получит успокаивающее интервью. Ложноотрицательный триаж — реальный риск, и он в материалах не обсуждается.
- **Точность не измерена нигде**: ни WER на медицинской лексике (хотя `keyterms` заданы именно для этого), ни точность ESI против клинического стандарта, ни полнота детекции взаимодействий. При 44 тестах отсутствие хотя бы одного теста качества распознавания заметно.
- **Render free plan**: сервис спит через 15 минут, пробуждение 30–60 с. Совет «держите таб открытым или пингуйте `/api/health`» означает, что демо хрупкое по конструкции.
- **Прямое подключение браузера к AssemblyAI** (страница коннектится с `?token=`) означает, что аудио пациента идёт мимо сервера — хорошо для латентности, но раздел приватности сам признаёт: «no PHI leaves the stack **except the live audio session**». Для медицинского контекста в США это BAA-вопрос, который не поднят.
- **Пересечение ниши с Veritas**: два медицинских голосовых проекта в одной группе. Если судьи захотят разнообразия, один проиграет по Originality просто за дубликат категории — и Veritas выглядит богаче по объёму, а VoiceMed сильнее по технике.
- **Originality — относительно слабое место проекта.** «Голосовой медицинский триаж» — один из самых предсказуемых сюжетов голосового хакатона. Исполнение великолепное, но идея не удивляет.
- Тэги на девпосте (`Advertising, Coding, Developer Tools, Designer Tool Plugin, Desktop Application, Mental Health`) выглядят как ковровое проставление категорий — мелочь, но читается как попытка попасть в максимум треков.

**8. Чем это можно побить**

Это главный конкурент по «Application of Technology», и лобовая атака проиграет. Побить можно в трёх местах:

1. **Ударить в латентность, где у них единственное измеренное число — плохое.** Их доказанная цифра — 5.63 s до приветствия, turn-to-turn они не измеряли. Наш ход: **опубликовать полную таблицу turn-to-turn латентности** — время от конца речи пользователя до первого байта ответного аудио, p50/p95, отдельно с вызовом инструмента и без, со скриптом воспроизведения. Если у нас p95 < 1.5 s на ход, мы говорим «реальное время», а они — «5.6 секунды до первого слова». Это сравнение на слайде выигрывается мгновенно.
2. **Ударить в глубину данных, где они игрушечные.** 20 симптомов и 20 пар взаимодействий против настоящего источника (полноценный справочник, RxNorm/DrugBank-подобный набор) — и главное, **измеренная полнота**: «на N-элементном тестовом наборе: recall X%, precision Y%». Они не могут показать ни одной цифры качества, только цифры протокола. Business Value решается именно здесь: судья спрашивает «можно это выпустить?», и ответ «наша база покрывает 20 пар» — это нет.
3. **Забрать Originality, которую они не защищают.** Медицинский триаж предсказуем, и среди разобранныхих двое. Наш ход — та же техническая глубина Voice Agent API (tool queue/flush по `reply.done`, `execution_mode`, barge-in через ring buffer, одноразовые токены, гарантированный `session.end` — всё это надо воспроизвести обязательно, иначе мы проигрываем по технике), но применённая к нише, где голос не удобство, а **единственный возможный интерфейс**. При равной технике мы забираем Originality и не делим категорию ни с кем.
4. **Скопировать три их приёма без обсуждения** — они слишком хороши, чтобы не взять: (а) `smoke_test.py`, который живьём валидирует протокол против реального эндпоинта и печатает тайминги по шагам — объективное доказательство, которого нет ни у кого; (б) Demo Copilot, который ведёт презентующего по репликам и авто-продвигается — страховка от провала живого демо; (в) always-on хостинг с WebSocket и объяснением выбора, но **на платном тарифе**, чтобы не иметь их 30–60-секундного пробуждения.
