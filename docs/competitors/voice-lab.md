**1. Что построено**

Голосовой научный копилот для молекулярной симметрии: пользователь говорит «Analyze BF₃ and tell me its point group», система достаёт структуру (PubChem), нормализует геометрию, определяет элементы и операции симметрии, разрешает точечную группу, строит матричные представления и характеры, редуцирует приводимое представление по таблице характеров, проверяет операции на геометрии и показывает всё в 3D (3Dmol.js) плюс в «Research Replay» — аудируемой последовательности научных событий. Слоган: «**Most voice agents can talk. VoiceLab can calculate and verify**», принцип — «AI orchestrates. Science computes».

**2. Как использован AssemblyAI**

**Самая слабая интеграция среди разобранных — и это главная проблема проекта на хакатоне AssemblyAI.** В разделе Technology написано буквально: «**AssemblyAI** — voice-agent / speech interaction» и отдельной строкой «**LiveKit** — real-time voice infrastructure». То есть реальный реалтайм-транспорт — LiveKit, а AssemblyAI — один из блоков в нём. В зависимостях: `requirements.txt` содержит просто `assemblyai` (без версии) и `websockets>=14.0`, а рядом лежат отдельные `requirements-livekit.txt` и **`LIVEKIT_MIGRATION.md`** — документ о миграции на LiveKit. Плюс `.env.livekit.example`. Прямая улика: голосовой слой уезжает с платформы организатора.

Ни одна фича AssemblyAI не названа конкретно: нет ни модели (Universal-3 / 3.5), ни tool calling, ни LeMUR, ни LLM Gateway, ни speaker labels, ни turn detection, ни формата аудио, ни эндпоинта. В блок-схеме стоит обобщённое «AssemblyAI Voice Agent / STT / Turns». Объяснение концепций теории групп отдано **Gemini** («gemini-ai - For explanation of concept for group theory»). По Application of Technology в части AssemblyAI предъявить почти нечего.

**3. Архитектура и стек**

Python 3.10+ · FastAPI + uvicorn · websockets · NumPy · Jinja2 · AssemblyAI SDK · LiveKit · PubChem · 3Dmol.js · SQLite/PostgreSQL (`psycopg[binary]>=3.2,<4`) · Docker + docker-compose. Структура: `app/agent/` (состояние и оркестрация), `app/science/` (симметрия и теория групп), `app/tools/`, `app/voice/` (AssemblyAI/LiveKit), `app/report/`, `app/web/`. Запуск двумя скриптами: `./start-production.sh` и `./start-voice-agent.sh` — веб и голосовой агент это два отдельных процесса. Персистентность описана отдельными документами (`POSTGRES_PRODUCTION.md`, `PRODUCTION_PERSISTENCE.md`).

Поток аудио как таковой в README не описан вообще — ни частота дискретизации, ни кодек, ни буферизация, ни barge-in. Для голосового хакатона это симптоматично.

**4. Настоящая инженерная суть**

Настоящая суть здесь есть, но она **не голосовая**. Детерминированный слой симметрии — это реальный код: нормализация геометрии, обработка главной оси, генерация операций симметрии, картезиановы преобразования, матричные представления, вычисление характеров, редукция по таблице характеров, геометрическая верификация. Для BF₃ выдаётся `D₃h`, `12 symmetry operations`, `12 / 12 verified PASS` и `Γ(x,y,z) = E′ + A₂″` — и это **корректно** (в D₃h картезиановый базис действительно раскладывается как E′ + A₂″), что говорит о том, что математика написана, а не сочинена. Архитектурный принцип «LLM не является источником численной истины» правильный и хорошо артикулированный.

Голосовая же часть — тонкий слой intent-парсинга поверх чужого транспорта. «Scientific Intent / Agent Orchestration» на диаграмме — единственный блок между голосом и наукой, и его устройство не раскрыто.

**5. Метрики и доказательства**

Цифры есть, но их ровно четыре, и все про один пример: `BF₃ → D₃h`, `12 operations`, `12 / 12 PASS`, `Γ(x,y,z) = E′ + A₂″`. Покрытие молекул честно ограничено тремя примерами: «H₂O, NH₃, BF₃». Раздел Testing перечисляет области покрытия (симметрия, точечные группы, преобразования, представления, характеры/редукция, геометрическая верификация, реестр молекул, контракты персистентности, **voice-flow smoke tests**, научные регрессии) — но **ни одного числа**: ни количества тестов, ни покрытия, ни результата прогона.

Формулировки уклончивы по всему README: «The scientific layer **supports**…», «The workflow **can include**…», «VoiceLab **includes** PubChem-related components» — это язык «реализовано частично», а не «работает». Латентности нет ни одной цифры, и авторы сами пишут в Limitations: «Latency can vary with external services». Раздел Limitations, к их чести, честный и подробный (8 пунктов), включая «Molecular and point-group coverage is limited to implemented workflows».

Отдельный сигнал: в корне лежат `PRODUCTION_AUDIT_REPORT.md`, `PRODUCTION_DEEP_DEBUG_REPORT.md`, `STAGING_CHECKLIST.md`, `apply_ch4_td_fix.py`, `FOLDER_STRUCTURE.txt`, `README_WINDOWS_SAFE.md`, `CACHEDIR.TAG` — порядка 17 markdown-файлов в корне при **4 коммитах**. Документация сгенерирована быстрее, чем код. Файл `apply_ch4_td_fix.py` («CH4 → Td fix») прямо говорит, что четвёртая молекула лечилась патч-скриптом в корне репозитория.

**6. Сильные стороны**

Самая сильная и защищаемая **идея о доверии** среди разобранных: голос понимает, детерминированный код считает, верификация подтверждает, Research Replay делает результат аудируемым. Ровно тот ответ, который судья хочет услышать на вопрос «как вы боретесь с галлюцинациями». Originality высокая: голосовых научных копилотов с настоящим вычислительным ядром на хакатонах почти не бывает, ниша (химия / теория групп) не пересекается ни с кем. Есть живое демо на своём домене, готовый `DEMO.md` («judge-ready demo script»), Docker-упаковка и корректный математический результат, проверяемый по учебнику.

**7. Слабые места и уязвимости**

- **Это не голосовой проект, это химический проект с голосовым вводом.** На хакатоне Voice Agent API это фатально: LiveKit в стеке + `LIVEKIT_MIGRATION.md` + ни одной названной фичи AssemblyAI. Первый же вопрос судьи — «что именно из Voice Agent API вы использовали?» — остаётся без ответа.
- **4 коммита при ~17 документах в корне.** Соотношение кода к документации выдаёт, что README продаёт то, чего в коде может не быть. Формулировки «can include» / «supports» — непроверяемые обещания.
- **Покрытие три молекулы.** Вся демонстрация — один BF₃. `apply_ch4_td_fix.py` намекает, что добавление CH₄ (Td) потребовало ручного патча: обобщения нет, каждая новая молекула это работа.
- Видео нет — при том, что весь продукт про «скажи и получи». Для судьи, который не станет разворачивать Docker, отсутствие записи означает, что голосовая часть не подтверждена вообще.
- Business Value узкая: студенты и преподаватели курса по теории групп. Тег на lablab — «Education». Готовность платить не обозначена, монетизация не описана.
- Голосовой поток не описан технически (нет sample rate, barge-in, latency) — по Application of Technology начислять баллы не за что.
- Команда один человек (Pawan Kumar Gayari), теги сабмита «Gemini AI, Codex, ChatGPT» — AssemblyAI даже не в списке инструментов.

**8. Чем это можно побить**

Их сильная сторона — «детерминированная проверяемость», и её надо перенять, а не оспаривать. Ход: **сделать верифицируемый контур там, где он касается именно голоса** — доказать не математику, а качество распознавания и исполнения в нашем домене: словарь и термины, WER до и после кастомизации словаря AssemblyAI, доля корректно распознанных именованных сущностей, процент tool-вызовов с валидными аргументами на N прогонах. Тогда наш trust model покрывает голосовой слой, а их — только химию. Второй ход, убийственный на Q&A: подчеркнуть, что у нас **реалтайм-транспорт целиком на AssemblyAI Voice Agent API, без LiveKit**, с названной моделью, tool calling и barge-in — мы решаем задачу организатора, они мигрируют с его платформы. Третий: покрытие. Их 3 молекулы против нашего «работает на произвольном входе» — пусть покажут четвёртую молекулу на сцене.
