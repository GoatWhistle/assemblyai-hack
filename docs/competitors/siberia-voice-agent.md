**1. Что построено**

Мульти-тенантный голосовой слой для SaaS-ассистентов: любой бизнес включает «Talk» на своей публичной чат-странице и получает голосового агента, который отвечает по его собственной базе знаний (цены, часы, услуги, адрес, акции) и захватывает лиды прямо в разговоре. Формула авторов: «one row = one voice assistant with your knowledge and lead capture». Репозиторий — **не приложение, а выделенный voice-слой** из проприетарного SaaS Frantal Siberia, опубликованный как MIT reference implementation.

**2. Как использован AssemblyAI**

Самое **широкое по площади API** использование среди разобранных, с таблицей «фича → файл»:

- **Провижининг агентов через REST**: `POST /v1/agents` и `PUT /v1/agents` в `AssemblyAiAgentService::provision` — конфиг бизнеса маппится в агента AssemblyAI (voice-first system prompt, greeting, язык-совпадающий голос, keyterms, два HTTP-инструмента), возвращённый `agent_id` сохраняется на тенанте. Единственный проект здесь, создающий агентов серверно, а не конфигурирующий сессию инлайном.
- **HTTP tools (server-side)**: `search_knowledge` и `capture_lead` — AssemblyAI сама ходит на наши эндпоинты (`VoiceToolController`), результат подаётся модели. Защита — middleware `VoiceToolAuth` по заголовку `X-Voice-Secret`.
- **Single-use session token**: `GET /v1/token` в `VoiceSessionController`, ключ не покидает сервер.
- **WebSocket-протокол**: `session.update{agent_id}`, `input.audio`, `reply.audio` в `src/frontend/voice-agent.js`.
- **Keyterms** из базы знаний как bias транскрипции (`keyterms()`).
- **Multilingual** через `input.language_codes` + нативный голос (`resolveVoice()` / `languageCodes()`), pt/en/es/fr.
- **BYO или managed LLM** через `llm[]` (`llmConfig()`); по умолчанию managed AssemblyAI, опционально свой OpenAI-совместимый эндпоинт («we run a Fireworks-backed shim»).
- **Semantic turn-taking и barge-in** — честно помечено «left on default».

Модель: **Universal-3.5**. Отдельно есть `VoiceDoctorCommand` — диагностика: `GET /v1/agents/{id}` + проверка достижимости инструментов.

**3. Архитектура и стек**

Laravel 13 / PHP 8.3, MySQL/SQLite; фронт — dependency-free JS-модуль + AudioWorklet (`pcm-processor.js`, PCM16 @ 24 kHz, «Firefox/Safari-safe resampling» — единственный проект, прямо заявляющий кросс-браузерный ресемплинг). Artisan-команды `siberia:voice-provision` и `siberia:voice-doctor`. Поток: браузер берёт short-lived токен → WebSocket к AssemblyAI → микрофон PCM16/24 kHz → AssemblyAI делает STT/LLM/TTS → при бизнес-вопросе AssemblyAI **серверно** вызывает `/api/voice/{slug}/search-knowledge` (RAG по тенантной БЗ) или `/api/voice/{slug}/capture-lead` (создание лида + письмо владельцу + нотификация в дашборд) → аудио-ответ в браузер. Требуется публичный HTTPS: «AssemblyAI calls your tools… `localhost` is rejected».

**4. Настоящая инженерная суть**

Реальная сложность — **мульти-тенантность и провижининг**, а не аудио. Нетривиальны три места:

(а) **Декларативный маппинг конфигурации бизнеса в агента AssemblyAI** с автоматическим извлечением keyterms из базы знаний. Правильный архитектурный выбор: биасинг транскрипции названиями услуг/товаров конкретного бизнеса — самый дешёвый способ поднять точность на доменной лексике, и почти никто в хакатоне так не делает.

(б) **Server-side HTTP tools вместо client-side.** Разница принципиальная: инструменты клиента можно подделать из браузера, серверные — нет; плюс это работает, даже если браузер закрылся на середине хода. Аутентификация через `X-Voice-Secret` — минимально достаточная (не HMAC, но шаред-секрет хотя бы есть).

(в) **`siberia:voice-doctor`** — команда, читающая живого агента из API и проверяющая достижимость инструментов. Признак человека, который реально эксплуатировал интеграцию, а не собрал демо.

Что тут **не** инженерия: RAG назван «RAG», но деталей нет — ни эмбеддингов, ни векторного стора, ни чанкинга, ни ранжирования. При MySQL/SQLite в стеке это, скорее всего, keyword/LIKE-поиск или full-text index, то есть retrieval очень простой. Turn-taking и barge-in «left on default» — собственного вклада в разговорную динамику нет. И главное — **в репозитории нет работающего приложения**: «it expects the host app to provide `Assistant`, `KnowledgeBase`, `Lead` and settings models», инструкция начинается со «скопируйте `src/laravel/*` в свой Laravel-проект и поправьте неймспейсы».

**5. Метрики и доказательства**

**Ноль.** Нет тестов (нет ни PHPUnit/Pest конфига, ни `composer.json` — вообще нет манифеста зависимостей), нет замеров латентности, нет данных о качестве RAG, нет WER по языкам, нет метрик конверсии лидов. **5 коммитов** — минимум среди пяти из разобранных. Отсутствие `composer.json` означает, что проект в этом виде даже не устанавливается. Числа, которые есть, — только конфигурационные: 4 языка (pt/en/es/fr), 2 HTTP-инструмента, PCM16 @ 24 kHz, Laravel 13 / PHP 8.3. Заявления «low-latency speech» и keyterms «to boost transcription accuracy» — **непроверяемые: ни одного замера**.

**6. Сильные стороны**

По Application of Technology площадь покрытия AssemblyAI лучшая: REST-провижининг агентов, server-side HTTP tools, токены, keyterms, multilingual, BYO-LLM, диагностика. Это видно сразу и читается как «человек прочитал всю документацию, а не quickstart». Бизнес-модель самая готовая: это уже работающий SaaS с реальными тенантами, voice — апселл к существующему продукту; «most businesses can't afford a phone operator» — понятная боль с понятным чеком. Мульти-тенантность и embeddable-виджет дают немедленный путь к монетизации. MIT reference implementation — симпатичный жест для сообщества и, вероятно, часть причины #2 по голосам (плюс оформленный README с бейджами, mermaid-диаграммами и живой демкой).

**7. Слабые места и уязвимости**

Инженерия **не соответствует** позиции #2, уязвимости грубые:

- **Это не запускаемый проект.** Нет `composer.json`, миграций, моделей, host-приложения. «Copy `src/laravel/*` into your Laravel app (adjust namespaces/models)» — судья не воспроизведёт ничего. По сути в репозитории лежат семь файлов-сниппетов.
- **5 коммитов.** Код явно вырезан из приватного монорепо одним движением. Работа «в течение хакатона» недоказуема — истории нет. Прямой вопрос к правилам: какая часть сделана на хакатоне, а какая существовала до?
- **Проприетарное ядро вне репозитория**: «The full Siberia SaaS (billing, admin, tenant management) is proprietary and not included here». Демо показывает продукт, которого в репозитории нет — судья оценивает не то, что видит в коде.
- **Ноль тестов, ноль цифр.** Утверждения о latency и accuracy не подкреплены ничем.
- **RAG — чёрный ящик.** Ключевая фича («speaks with the business's own knowledge») описана одним словом, без эмбеддингов, стора и метрик релевантности. Вероятно, keyword search.
- **Собственного вклада в голосовую динамику нет** — turn-taking/barge-in «left on default». Честно, но по Originality в голосовой части вклада не остаётся: оригинальность вся в мульти-тенантном контуре, которого в коде нет.
- `X-Voice-Secret` — статичный шаред-секрет без подписи и timestamp: реплей-атака на `capture_lead` возможна, а эндпоинт создаёт записи и рассылает письма.
- Артефакты небрежности в корне: `LICENSE\` (файл с бэкслешем) рядом с `LICENSE`.
- Нет видео.

**8. Чем это можно побить**

Против #2 работают две вещи: **воспроизводимость** и **измеримость**.

Ход 1: **однокомандный запуск.** У них — «скопируйте файлы в свой Laravel и поправьте неймспейсы». Если у нас `git clone` + одна команда + открыть localhost и это работает у судьи с первого раза, мы выигрываем по Presentation и Application of Technology автоматически, потому что судья *проверил* нашу работу и *не смог* проверить их.

Ход 2: **сделать RAG настоящим и показать числа.** Они заявили RAG без деталей — значит любая измеренная retrieval-метрика (recall@k на 30 вопросах по БЗ + сравнение «с keyterms / без keyterms» по точности распознавания доменных терминов) бьёт их заявление наотмашь. Keyterms из БЗ — их лучшая идея; повторить её и **замерить** значит забрать её себе.

Ход 3: **подписанные tool-вызовы** (HMAC + timestamp + nonce) вместо статичного `X-Voice-Secret`, с тестом на реплей. Их `capture_lead` пишет в БД и отправляет почту по статическому заголовку — конкретная security-разница на один слайд.

Ход 4: **история коммитов как доказательство.** При 5 коммитах у них нет ответа на «что сделано во время хакатона». Осмысленная датированная история — бесплатное преимущество.
