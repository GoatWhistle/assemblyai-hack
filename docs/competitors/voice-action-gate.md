# Voice Action Gate (franciseliang99-dot)

**Тир:** A — Сильные  
**Чем силён:** Лучшая идея хакатона: capability вместо if, witness строится до появления предложения  
**Где пробивается:** Живой путь браузер→WS→гейт не прогонялся ни разу. Агент — regex. READ_BACK_CONFIRMED не реализован. 7 коммитов

**1. Что построено**

Голосовой агент, который **не может выполнить необратимое действие без доказуемого подтверждения** — не «старается не ослышаться», а структурно: код, исполняющий действие, принимает только Execute-credential (capability), и у этого credential ровно одна точка создания — гейт. Гейт минтит его только если **каждый** аргумент предложенного действия заземлён (grounded) в witness-е, построенном из word-level транскрипта AssemblyAI. Формулировка README: *«"I couldn't tell" has no path to "go ahead"»*. Демо — Cloudflare Worker, где можно нажать «Use a sample instead» → «Ask the gate» и воспроизвести три отказа: подделанная сумма, неверно услышанное имя, и голое «dollars» без указания, чьи.

**2. Как использован AssemblyAI**

**Universal-Streaming v3** + **Voice Agent API**, с опорой на client-side function tools: агент эмитит `tool.call`, код исполняет логику, возвращается `tool.result` — гейт садится ровно в этот шов, и README справедливо отмечает, что это документированная архитектура, а не найденный хак.

Входы гейта перечислены как «verified, not assumed»:
- **word-level `confidence`** и `word_is_final`, по слову, на каждом `Turn`
- **тайминги слов** (`start`/`end`, миллисекунды)
- **`end_of_turn_confidence`**
- аргументы предлагаемого `tool.call`

Аудио идёт **браузер → AssemblyAI напрямую**, так что Worker видит только слова; это разделение закреплено mutation-арм-тестом, который краснеет, если его нарушить. Worker минтит токен с обоими duration cap-ами (§5.7 архитектурного документа).

Важно: `READ_BACK_CONFIRMED` — пятый вход, который API дать не может, — **специфицирован, но не реализован**, отгружен как `NOT_REQUIRED` (то есть пропускается). Авторы пишут это сами: «an interface slot with no implementation… It is a design commitment, not something you can demo.»

**3. Архитектура и стек**

Гейт — **чистый Python без зависимостей** (`python3 -m unittest discover -s tests -t . -q`), что даёт портируемость. Деплой — **Cloudflare Python Workers**, сборка `app/build.sh` вендорит гейт + runtime в `app/worker/`. Дневной лимит выдачи токенов — в **Durable Object, а не KV** (сознательное решение ради строгой консистентности). `GET /api/health` возвращает `{"ok": true, "python": "3.13.2"}`. Локальный e2e — `app/run_local.sh` против dev-сервера, печатает строку на каждое решение гейта, нужен `.dev.vars`. Раскладка: `gate/` (в т.ч. `gate/witness.py` — собственно grounding, `gate/reference.py` — независимо объявленный реестр требований), `app/`, `tests/`, `docs/`, `media/`, плюс `.export-manifest.json`.

Аномалия в корне: `LICENSE` и `LICENSE\` — дубликаты с backslash, то есть репозиторий заливался скриптом, сгенерировавшим битые пути.

**4. Настоящая инженерная суть**

Три идеи, и все три настоящие:
- **Capability вместо проверки.** Разница существенная: `if (checks_passed) execute()` обходится новой ветвью кода; `execute(cap: ExecuteCapability)` нельзя вызвать без объекта, который умеет создавать только гейт. Это перенос корректности из дисциплины в конструкторы.
- **Witness-множество строится из транскрипта ДО того, как предложение видно.** Ключевая деталь, объяснённая правильно: иначе модель, выдумавшая число, сама выбирает поисковый запрос, и любое несвязанное число становится её доказательством. Порядок операций здесь и есть безопасность.
- **Нормализатор как частичная функция.** `"five hundred"` → `500` — «машина по производству свидетелей»: нормализуй достаточно агрессивно, и любое значение найдёт «доказательство» себе. Поэтому нормализатору разрешено отвечать `UNDECODABLE`, и `UNDECODABLE` — не пропуск: «A normalizer with a fallback return value quietly converts "I cannot read this" into "I believe it equals something" — the direction that costs money.»
- Асимметрия отказов спроектирована явно и вынесена в таблицу: неверный блок = пользователь повторил фразу («Annoying»); неверный пропуск = «Money moved. Irreversible.»

Агент в демо — **намеренно regex**, «so that being wrong is the normal case». Методологически честно, но см. слабости.

**5. Метрики и доказательства**

Редкая вещь: в README **встроены редакционные правила** в HTML-комментариях, первое — «NO UNMEASURED NUMBERS… Never write a plausible-looking figure "to calibrate later": a number in a README gets quoted back as a conclusion», и вместо цифр стоят `MEASURE`-маркеры. Даже WER не указан, потому что не нашли цитируемого источника.

Что измерено:
- **152 теста**, с цитированием ID спецификации (`TS-01`…`TS-49`, `A0`…`A24.6`, `DN-1`); каждый тест самоописателен в docstring.
- **Строгая консистентность счётчика дневной выдачи, измерена на Cloudflare 2026-09-03**: 12 конкурентных вызовов `/api/token`, **66 из 66 in-flight интервальных пар перекрываются**, `issued` 16…27 — различные и непрерывные, ноль дубликатов, 0.77 с wall против 2.26 с последовательной нижней границы. С немедленной оговоркой: «That is one concurrency level on one day — not a proof that the property holds at arbitrary concurrency, or across DO eviction and migration.»
- **Измеренная самокритика реестра**: «The registry lint is weaker than an earlier draft of this README claimed» — он отвергает `NOT_IMPLEMENTED` проверки на необратимых действиях, но не `NOT_REQUIRED`, а развёрнутый реестр **производен от** таблицы чекеров, с которой lint его затем сравнивает, так что удаление чекера оставляет проверку зелёной (измерено, 3/3, 2026-09-03). И lint выполняется на каждый запрос внутри `build_gate()`, а не однажды на старте. Зато сам grounding в `gate/witness.py` держится: удали один чекер — подделанная сумма всё равно блокируется; удали два — проходит.

Чего нет, и это сказано прямо: **полный путь браузер → живой WebSocket → реальный транскрипт → гейт → исполнение не прогонялся end to end ни разу.**

Демо: живой Worker, видео 4:16 1920×1080 на YouTube (unlisted) + `media/demo.mp4` + `media/demo.srt` (SRT — это текст, который рендерился в дорожку нарратива, а не пост-фактум транскрипт), `media/slides.pdf`, `media/cover.png`.

**6. Сильные стороны**

- **Originality — сильнейшая среди разобранныхпо идее.** «Capability, которую нельзя сконструировать без доказательства» — не хакатонный трюк, а дизайн-паттерн, переносимый в продакшн. Три названные идеи (witness до предложения, частичный нормализатор, capability вместо if) переиспользуемы вне проекта.
- **Интеллектуальная честность возведена в процесс**: редакционные правила прямо в файле, секция «Honest limits» с пометкой «🔴 DO NOT DELETE THIS SECTION» и объяснением зачем («"Our threat model excludes this" and "we didn't think of it" look identical in a demo; only one of them is written down in advance»), исправление собственного README как измеренный факт, disclosure про использование ИИ-ассистентов, clean-room заявление.
- **Демо не требует микрофона** — три ghost-кнопки воспроизводят три отказа. Снимает риск «у судьи не заработал микрофон».
- Использование word-level `confidence` и `end_of_turn_confidence` — фичи AssemblyAI, которые почти никто в хакатоне не трогает.
- Threat model прописан явно, включая то, что вне него: злонамеренный клиент (но противник здесь — языковая модель, а человек у микрофона — защищаемая сторона; «Forging your own transcript is lying to yourself») и внутренне-консистентный неверный транскрипт («The gate proves provenance, not truth»).

**7. Слабые места и уязвимости**

Самый большой среди разобранныхразрыв между идеей и реализацией — задокументированный самим автором, что смягчает удар, но не отменяет его:
- **Полный путь не прогонялся end-to-end.** Судья по Application of Technology вправе сказать: голосового агента как работающей системы здесь нет. Живёт Worker и чистый Python-гейт, а **живой аудиопуть через Voice Agent API не проверен ни разу**.
- **«Агент» — это regex.** Намеренно, но следствие: **ни одной строки реального взаимодействия с LLM-агентом AssemblyAI в работающем виде**. Tool calling описан как шов, но не показан в работе на живой сессии.
- **`READ_BACK_CONFIRMED` не реализован** — а это, по собственному описанию, тот единственный вход, который API дать не может, то есть авторский вклад. Отгружено как `NOT_REQUIRED` = пропускается. Самая человеческая часть защиты отсутствует.
- **Реестр lint зелёный при удалённом чекере** — автор нашёл и написал, но дырка на момент сдачи живая, и находится ровно в механизме, который продаёт проект («структурная невозможность»).
- **7 коммитов** — меньше всех среди разобранных, при 152 тестах и Cloudflare-деплое. README утверждает «everything in this repository was committed inside the hackathon window», но 7 коммитов — это либо squash, либо один гигантский залив; `LICENSE\` дубликат это подтверждает.
- **Ключевой дизайн-документ вне репозитория**: «That document is the development record and is not part of this submission — it lives outside this repository.» Тесты цитируют ID из документа, которого судья не видит. Ровно то, что судья не может проверить.
- Архитектурный документ **написан на китайском**, английский только §0. Для международного жюри это фрикция.
- Метрика консистентности DO — **инфраструктурная**, не про голос. Единственное серьёзное измерение проекта не касается речи вообще.
- **Никаких данных о качестве grounding**: сколько легитимных действий гейт заблокирует ложно? Асимметрия заявлена как принцип, но false-reject rate не измерен ни на одной выборке. Если гейт блокирует 40% честных транзакций, продукт нежизнеспособен — и это неизвестно.
- В конце README — **саморекламная секция** («Who built this», ссылка на собственную страницу «Security Gate Pass», «If the idea… is a problem you have, that page has a way to get in touch»). Часть судей воспримет как использование сабмишена под лидоген.

**8. Чем это можно побить**

Их уязвимость точечная и смертельная: **идея сильнее реализации, живой путь не прогонялся**. Ход — реализовать их собственную идею целиком и прогнать на живом аудио: (а) grounding из word-level транскрипта, как у них; (б) **реализованный** read-back confirmation, привязанный к транскрипту подтверждения, а не к сводке модели — ровно тот слот, который они оставили пустым; (в) полный прогон браузер → Voice Agent WS → реальный транскрипт → гейт → исполнение с логом решений; (г) **измеренный false-reject rate** на N честных транзакциях и false-accept на N adversarial (подмена суммы, подмена получателя, выдуманное значение). Мы предъявляем матрицу 2×2, они — дизайн-документ на китайском вне репозитория.

Второй ход — **сделать mutation testing первоклассным доказательством, а не оговоркой**. Они признались, что реестр зелёный при удалённом чекере. Мы показываем mutation score: «удаление любого одного из N чекеров ломает ≥1 тест, `make mutate` выдаёт N/N» — то же оружие, но заряженное.

Третий — **capability + аудит**. Их credential доказывает provenance, но не оставляет следа. Подписанный аудит-лог решений гейта (что минтили, что отказали, какой witness) делает «доказуемое подтверждение» доказуемым **после** факта, а не только в моменте. Закрывает то, что у них прямо названо вне охвата.
