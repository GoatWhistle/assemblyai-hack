**1. Что построено**

Заявлено: «defense-grade» платформа амбиентного клинического интеллекта и автономного управления циклом дохода (RCM). Слушает разговор врача с пациентом, выдаёт диаризованный транскрипт, синтезирует структурированную SOAP-заметку с ICD-10 дифдиагнозами и классификацией сложности MDM, параллельно принимает изображения 12-канальной ЭКГ и извлекает ST-девиации, проверяет лекарственные противопоказания, аудирует кодирование по правилам AMA/CMS и генерирует готовые к отправке EDI-клеймы ANSI ASC X12N 837P (5010X222A1) плюс FHIR R4 бандлы.

Объём заявленной функциональности при **13 коммитах** — первое, что должно насторожить.

**2. Как использован AssemblyAI**

Технически названо корректно и конкретнее, чем у SmartLink:

- **AssemblyAI Streaming v3, Universal-3.5 Pro** — именно так, с версией API и моделью.
- **Web Audio API, 16 kHz PCM**, «frame chunking piped over WebSockets» — параметры потока указаны (16 kHz несжатый PCM; для Voice Agent API типичны 24 kHz, но здесь это Streaming STT, и 16 kHz уместно).
- **Спикерская диаризация в реальном времени** — «sub-second speaker-diarized transcripts (Doctor vs. Patient)», в devpost «zero-latency speaker separation».

И здесь техническая претензия, в которую судья с опытом упрётся мгновенно: **Streaming v3 не даёт настоящих speaker labels в реальном времени** — диаризация в AssemblyAI относится к асинхронной транскрипции. «Zero-latency speaker separation» на стриминге — либо собственная эвристика (по паузам или каналам), либо неточное описание. Ни README, ни devpost не объясняют, как именно достигается разделение Doctor/Patient. Это заявление первого порядка, и оно ничем не подкреплено.

Чего нет: **Voice Agent API не используется** — нет tool calling на стороне AssemblyAI, нет TTS от AssemblyAI, нет semantic turn detection. Ключевое «reasoning» отдано **Google Gemini 2.5 Flash** с «512-token thinking budget» и 4096 max output tokens, зрение по ЭКГ — Gemini Multimodal Vision. То есть AssemblyAI здесь — один модуль транскрипции из разобранных, а мозг проекта чужой. На спонсорском хакатоне это структурно невыгодная позиция. Заявленные «bidirectional voice commands» и голосовой вызов `tool_resolve_denial` не сопровождаются указанием, чем реализован исходящий голос — TTS-провайдер не назван вообще.

**3. Архитектура и стек**

Backend: Python 3.10+ («Python 3.11–3.14 verified»), FastAPI, uvicorn, Swagger на `/docs`, healthcheck `/api/health`. Frontend: Next.js 14. Оркестрация: `docker-compose.yml`, `docker compose up --build` поднимает оба контейнера (UI на :3000, API на :8000). Деплой заявлен на Vercel.

`top_level`: `.env.example`, `backend`, `frontend`, `assets`, `docker-compose.yml`, `README.md`, `LICENSE` и — внимание — **`LICENSE\`** (второй файл с обратным слэшем в имени). Артефакт кривой команды на Windows, попавший в коммит. Мелочь, но она говорит о культуре ревью.

`requirements_txt`, `pyproject_toml`, `package_json` в собранных данных **пусты** — манифесты лежат в подпапках `backend/` и `frontend/`; подтвердить стек по манифестам нельзя.

Поток: `Ambient Audio → AssemblyAI v3 Diarization → Gemini 2.5 Flash CDS ← Gemini Vision (ЭКГ) → Medico-Legal Airlock → CMS E/M 99215 RCM Radar → ANSI X12 837P Clearinghouse`. Диаграмма mermaid в README есть — единственный проект разобранных проектов с формальной схемой. Но в самой диаграмме стоит «Gemini **2.0** Multimodal Vision», тогда как в тексте везде 2.5 Flash — рассинхрон внутри одного документа.

**4. Настоящая инженерная суть**

Что здесь **действительно** нетривиально, если реализовано:

- **Генератор EDI ANSI ASC X12N 837P 5010X222A1** с правильными петлями: Loop 2010AA (Billing Provider), 2010BA (Subscriber), 2300 (Claim Information), 2400 (Service Line с указателями CPT/ICD-10). Знать номера петель 837P — не то, что придумывается на ходу; либо человек работал с клирингхаусами, либо очень внимательно читал спецификацию.
- **Матрица CMS 2-of-3 MDM** — оценка встречи по трём осям (число/сложность проблем, объём/сложность проанализированных данных, риск осложнений) для обоснования уровня E/M. Реальная, болезненная и дорогая предметная область.
- **Детерминированный «Medico-Legal Airlock»**, отделённый от вероятностной генерации: Warfarin+Aspirin (с целевым INR 2.0–3.0), Metformin+иодированный контраст (отмена за 48 ч), Lisinopril+калий (гиперкалиемия). Правильная архитектурная идея — та же, что у RevenueFlow: критичные решения отдать детерминированному коду.
- **HL7 FHIR R4 (v4.0.1)** бандл с ресурсами `Patient`, `Encounter`, `Condition`, `Observation` под SMART-on-FHIR.

Что **обёртка**: диаризация (вызов AssemblyAI), SOAP-генерация (промпт к Gemini), парсинг ЭКГ (загрузка картинки в Gemini Vision — «extracting ST-segment deviations» делает модель, не проект). Три из четырёх «Key Features» — это промпты к Gemini разной длины. Настоящий собственный код — EDI-генератор, FHIR-бандлер, таблица взаимодействий и MDM-матрица, и именно про них в README меньше всего технических деталей: ни одного имени файла, ни одной функции.

**5. Метрики и доказательства**

Здесь проект ломается. README содержит таблицу «Performance & Clinical Impact Benchmarks», и **каждая цифра в ней непроверяема**:

- «Chart Documentation Latency: 14–18 минут → **1.2 секунды** (Continuous), **92% Reduction**». Во-первых, 1.2 секунды на генерацию полной SOAP-заметки через Gemini 2.5 Flash с 512-token thinking budget и 4096 max output tokens физически сомнительно — 4096 токенов вывода это единицы-десятки секунд. Во-вторых, арифметика: 18 минут → 1.2 с это сокращение на 99.9%, а не 92%. **Цифры в одной строке не согласуются между собой.**
- «Payer Claim Rejection Probability: 12–18% → **4.0%**, 76% Denial Drop». Откуда 4.0%? Это требует прогона реальных клеймов через реального плательщика. Ни исследования, ни выборки, ни методологии.
- «E/M Coding Level Accuracy: 71.4% → **99.4%**, +28% Precision». 99.4% точности кодирования уровня E/M — заявление, которое в индустрии стоило бы миллиарды. Ни датасета, ни аудита, ни golden set.
- «Prior-Authorization Pre-Drafting: 48–72 часа → **3.4 секунды**».
- «Drug Contraindication Latency: **< 350 ms**».
- «Claim audit probability from **58% down to 4%**» — повторяется трижды в README и **приписывается заранее заготовленному демо-пресету** `[⚡ TELEHEALTH DENIAL DEMO]`, где риск «интерактивно решается с 58% до 4%». То есть это не измерение, а анимация в демо.
- «Slashes claim rejection rates from 12-18% **down to 4%**» — но в другой строке тот же 4% относится к «audit probability». **Метрики перепутаны между собой.**

**Тестов нет вообще.** Ни папки в `top_level`, ни раздела «Testing» в README — только «Interactive Evaluation & Testing Presets», то есть три кнопки демо-сценариев, а не автотесты. Это единственный проект разобранных проектов с нулевой верификацией при максимальных заявлениях.

Ссылка «▶ Watch Interactive Demo — Loom Walkthrough» **ведёт обратно на сам GitHub-репозиторий**, не на Loom. Ссылка «Live UI Demo» ведёт на **`http://localhost:3000`** — судья, кликнувший её, попадёт в никуда. Это не придирка: две сломанные кнопки в самом видном месте README.

Комплаенс-матрица («HIPAA Safe Harbor: 18 de-identification metrics strictly applied», «ONC HTI-1 Compliance», «CMS-0057-F Interoperability», «TLS 1.3 + AES-256-GCM», «Zero Persistent Audio Storage», «HL7 FHIR R4 v4.0.1», «ANSI ASC X12N 837P v5010X222A1») — набор галочек в ASCII-рамке **без единой ссылки на код или конфиг, который это обеспечивает**. Заявлять HIPAA-соответствие галочкой в README — это то, за что в реальном аудите отвечают.

13 коммитов при таком объёме — либо всё залито крупными порциями (история работы не прослеживается), либо большая часть сгенерирована.

**7. Слабые места и уязвимости**

- **Все бенчмарки — числа без источника.** Это главный рычаг. 1.2 с, 4.0%, 99.4%, 58%→4%, <350 ms, 3.4 с — ни методологии, ни датасета, ни скрипта воспроизведения. Одного вопроса «покажите, как вы измерили 99.4% точности E/M-кодирования» достаточно, чтобы обвалить весь раздел.
- **Внутренние противоречия в цифрах**: 18 мин → 1.2 с подписано как «92% Reduction»; 4% одновременно и «rejection rate», и «audit probability»; «Gemini 2.5 Flash» в тексте против «Gemini 2.0 Multimodal Vision» в диаграмме.
- **Две сломанные ссылки в шапке README**: Loom-демо ведёт на сам репозиторий, «Live UI Demo» — на `localhost:3000`.
- **Нулевые тесты.** При заявленном «defense-grade» и медицинском применении.
- **13 коммитов** — самая слабая история работы относительно объёма заявленного.
- **AssemblyAI — вспомогательный компонент.** Мозг это Gemini. На хакатоне AssemblyAI это минус по «Application of Technology», и таблица «почему Veritas побеждает» его не закрывает: в графе Technical Complexity первым пунктом стоит AssemblyAI, но вторым и третьим — Gemini.
- **Realtime-диаризация на Streaming v3 технически сомнительна** и никак не объяснена. Судья со стороны AssemblyAI заметит это быстрее всех.
- **Медицинская ответственность**: **нет дисклеймера «not a medical device»** (в отличие от VoiceMed, который ставит его дважды). Заявления «board-certified clinical notes», «stops fatal contraindications», «blocks adverse drug interactions before orders are placed» — претензия на функцию медицинского устройства, требующую регуляторного пути. При этом в README отдельно указано, что safety-фильтры Gemini **сознательно отключены**: «disabling overzealous safety filters on standard medical conditions (e.g. active bleeding, severe thrombocytopenia)». Отключить safety-фильтры в медицинском приложении и не поставить дисклеймер — самая опасная строка среди разобранных.
- **HIPAA/приватность**: галочки без реализации. «Zero Persistent Audio Storage» надо доказывать кодом, а не рамкой из ASCII. При этом аудио уходит в AssemblyAI, а данные встречи — в Google Gemini; ни слова о BAA (Business Associate Agreement), без которого обработка PHI сторонним API нарушает HIPAA. Этот укол убивает весь комплаенс-раздел целиком.
- **Признаки автогенерации и невычитанности**: файл `LICENSE\` с обратным слэшем, эмодзи в каждом заголовке, плотность маркетинговых прилагательных («defense-grade», «institutional excellence»), и **обрезанный на середине раздел `## 📂 Repository Str`** — README буквально обрывается посреди заголовка.
- **Автономные действия с деньгами**: «Autonomous 1-Click Payer Defense», «self-heals documentation deficiencies», то есть система сама дописывает обоснования медицинской необходимости в клейм, чтобы поднять его оплачиваемый уровень. Названный судьёй вслух, этот механизм звучит как **автоматизированный upcoding** — то, за что в США предъявляют по False Claims Act. Это не гипотетический риск, а прямое описание функции в их собственном README.

**8. Чем это можно побить**

Veritas выигрывает презентацией и проигрывает доказуемостью. Атаковать нужно ровно туда:

1. **Заменить их таблицу заявлений на таблицу измерений — и сказать это вслух.** Наш раздел метрик должен выглядеть так же красиво, но каждая строка — с методологией, размером выборки и командой воспроизведения (`npm run bench` / `pytest tests/bench`). Формулировка для слайда: «каждое число здесь получено этой командой, вот лог». Рядом с их «99.4% E/M accuracy» это выигрывает без спора.
2. **Использовать AssemblyAI как мозг, а не как микрофон.** У них reasoning на Gemini, AssemblyAI — транскрипция. Наш ход: **Voice Agent API как единственный рантайм диалога** — STT + LLM-оркестрация + TTS + semantic turn detection + client-side tool calling в одном WebSocket, с явным указанием модели (Universal-3.5) и `keyterms` для доменной лексики. По «Application of Technology» на спонсорском хакатоне это структурное преимущество, которое они не могут отыграть без переписывания.
3. **Забрать их сильнейший приём и починить то, что у них сломано.** Их zero-microphone демо-пресеты — умно, копируем. Но их Loom-ссылка ведёт на репозиторий, а «Live Demo» на `localhost:3000`. У нас должны быть: рабочее публичное демо, 90-секундное видео с живым звуком, все ссылки проверены. Это бесплатные баллы по Presentation против проекта, который в остальном оформлен лучше нас.
4. **Поставить корректную рамку ответственности там, где у них дыра.** Явный дисклеймер «not a medical device / not financial advice», никаких отключённых safety-фильтров, честный раздел «что мы НЕ делаем и почему» (не выставляем клеймы автономно, не дописываем обоснования в счёт, не храним аудио, PHI не уходит без BAA). Против их «autonomous payer defense» и снятых safety-фильтров это превращается в разговор о зрелости, где взрослые — мы. Судья, который держит в голове FDA и False Claims Act, оценит это выше, чем ещё одну цифру.
5. **Честность как оружие.** Их README не содержит ни одного «пока не работает». Раздел «известные ограничения: 3 пункта» делает всё остальное в нашем README достоверным и одновременно подсвечивает, что у них нет ни одного признанного ограничения при шести заявленных прорывах.
