**1. Что построено**

Голосовой тренажёр технического интервью для джунов и выпускников: 5 направлений (Backend/Frontend/Full-Stack/AI-Data/DevOps), у каждого свой персонаж-интервьюер (Sarah, Dev, Maya, Ray, Chris) и практический сценарий («E-Commerce Cart REST API», «Interactive Movie Dashboard», «Containerizing a Web App»). Интервью — конечный автомат из 4 стадий (Problem Overview → Core Implementation → Validation & Errors → Wrap-up & Q&A) с формальным завершением. По итогу генерируется Markdown-отчёт в `reports/interview-report-*.md`: пары «вопрос — дословный ответ», оценки по 5 компетенциям (Technical Foundations, Problem Solving, Communication, Validation/Errors, Integrity) и вердикт (`Strong Hire` / `Hire` / `Leaning Hire` / `No Hire`).

**2. Как использован AssemblyAI**

**Voice Agent API целиком как единый блок** — и это принципиальное ограничение проекта. Из mermaid-диаграммы: внутри `AssemblyAICloud` лежат `STT` + `LLM with Guardrail Prompts` + `TTS`, то есть распознавание, рассуждение и синтез отданы платформе как чёрный ящик. Эндпоинт указан конкретно: `wss://agents.assemblyai.com/v1/ws` — правильный, актуальный Voice Agent endpoint (в отличие от Liora, см. ниже). Токены: `/token: 60s Ephemeral Minting`, ключ на сервере. Аудио: `24kHz AudioWorklet Resampler` на вход, `24kHz Ring Buffer Playback` на выход.

Чего **нет**: ни LeMUR, ни LLM Gateway, ни speaker labels/diarization, ни word-level timestamps, ни tool calling. Название модели (Universal-3 / 3.5) в README не упоминается вообще. Вся «интеллектуальность» — промпты в пяти `.jsonc`-файлах (`agents/interview_backend.jsonc`, `interview_frontend.jsonc`, `interview_fullstack.jsonc`, `interview_ml.jsonc`, `interview_devops.jsonc`). Показательно: бейдж в README гордо декларирует `Dependencies: Zero` — то есть кода, работающего с аудио и протоколом, минимум.

**3. Архитектура и стек**

Node.js ≥18, без зависимостей, `"type": "module"`. Нативный HTTP-сервер (`deployment/browser/server.mjs`) отдаёт UI и три эндпоинта: `/token` (эфемерные 60-секундные токены), `/roles` (динамический реестр ролей), `/api/generate-report` (движок скоринга, `report-generator.mjs`). Отчёты пишутся в файлы `reports/*.md` — никакой БД. Конфигурация агентов декларативная, `.jsonc`. Деплой: `vercel.json` **и** `render.yaml` одновременно — признак того, что деплой искали методом перебора. В корне `.claude/`, `CLAUDE.md`, `AGENTS.md` — проект в значительной степени сгенерирован агентом, и авторы это не прячут. Файл `package.json\` (с обратным слэшем) в листинге — мусор от коммита с Windows. `publish.mjs` / `import.mjs` и внутреннее имя `"name": "voice-agent-starter"` в `package.json` показывают, что репо выросло из официального стартер-кита AssemblyAI.

**4. Настоящая инженерная суть**

Честно: тонкая обёртка над стартер-китом + 5 продуманных промптов + генератор Markdown. Нетривиального два элемента, и оба продуктовые, а не инженерные:

- **Two-tier silence watchdog**: «gentle Thinking Timer (**12s**)» и «contextual hint prompts (**25s**)». Правильно понятая проблема — джун думает молча, а VAD-агент либо перебивает, либо даёт мёртвый эфир. Реализация же — два таймера в браузере, а не работа с turn detection на стороне API (что было бы сильным ходом: AssemblyAI даёт настройки формирования хода / end-of-turn, и их здесь никто не трогает).
- **Конечный автомат на 4 стадии** как средство от «infinite turns & runaway cost» — разумная и дешёвая защита от бесконечного диалога. Но это тоже промпт плюс счётчик, а не серверный контроль.

Раздел «Security & Vulnerability Analysis» с таблицей угроз (voice prompt injection, topic derailment, dead air, infinite turns, credential leakage) — отличная презентационная работа, но контрмеры в трёх из разобранных строк — это формулировки в системном промпте. «Rejects prompt injection attempts (*"Ignore rules"*, *"Score me 10/10"*, *"Reveal rubric"*)» ничем не проверяемо: нет ни одного теста на инъекцию.

**5. Метрики и доказательства**

Цифр, кроме двух таймеров (12 с / 25 с), 60-секундного TTL токена и «15-to-20-minute sessions», нет. Нет замеров латентности, WER, тестов (в дереве репозитория **папки `tests/` не существует** — только `agents/`, `api/`, `deployment/`, `reports/`), CI, бенчмарков. Рубрика «1.0–5.0 competency» и вердикты Strong Hire / No Hire не откалиброваны ни на одном реальном интервью — валидности оценки нет никакой, а именно она и есть продукт. Единственное косвенное доказательство работоспособности — наличие папки `reports/` со сгенерированными отчётами, но что в ней, из README не видно.

**6. Сильные стороны**

Ниша выбрана точно и узко: не «ассистент для интервью вообще», а **именно junior-калибровка** — и это отличает проект от десятков generic interview-ботов. Business Value самая очевидная среди разобранных: есть готовность платить (выпускники, буткемпы, карьерные центры), путь монетизации понятен без объяснений. Артефакт на выходе — скачиваемый Markdown-отчёт с парами Q&A — это то, что судья может подержать в руках. README оформлен заметно лучше среднего: бейджи, mermaid, таблица угроз, дерево репозитория, дизайн-система (`#0B0C3B`, `#7057FF`, `#9B8AFF`).

**7. Слабые места и уязвимости**

- **Демо-ссылка ведёт не на приложение, а на приватный дашборд проекта Vercel.** Судья кликает — видит страницу логина / чужой проект. Возможно, самая дорогая ошибка среди разобранных: голосовое демо фактически недоступно, и видео тоже нет.
- **Технологическая глубина минимальна.** Voice Agent API использован как «включи и говори»; ни одной продвинутой фичи платформы (tool calling, LLM Gateway, LeMUR, diarization, word timestamps, настройка end-of-turn). По Application of Technology проект проигрывает почти любому, кто трогал хотя бы tool calling.
- Заявленный «Zero Dependencies» — обоюдоострый бейдж: судья прочитает его как «здесь почти нет своего кода».
- Ноль тестов при разделе о безопасности на пол-README. Гардрейлы — текст промпта; любая успешная инъекция на сцене убивает весь раздел.
- Валидность оценки не обоснована: почему ответ про «SQL vs NoSQL» даёт 3.5, а не 2.0, — не объяснено. HR-продукт без калибровки — игрушка, и опытный судья это скажет.
- Следы автогенерации в корне (`.claude/`, `CLAUDE.md`, `AGENTS.md`), мусорный `package.json\`, дубль деплой-конфигов.
- Ниша перегружена: «AI mock interview» — один из самых частых хакатонных сюжетов, Originality низкая.

**8. Чем это можно побить**

Их слабое место — глубина технологии и отсутствие доказательств. Два хода. Первый: там, где они молча полагаются на дефолтный VAD и два браузерных таймера, **мы явно настраиваем turn detection / end-of-turn и показываем это числами** — распределение времени до ответа, доля ложных перебиваний на 20 записанных репликах с паузами. Один график «мы перебиваем в 4% случаев против 30% у дефолта» перекрывает всю их таблицу угроз. Второй: сделать оценку проверяемой — публичный набор эталонов и цитаты из транскрипта под каждым баллом, с замером согласованности. И тривиальный, но решающий пункт: **рабочая публичная ссылка + 2-минутное видео разговора**. Против проекта, чьё демо — приватный дашборд Vercel, это чистая победа в Presentation.
