**1. Что построено**

Платформа голосовых обращений граждан для Кении: человек рассказывает голосом о проблеме («прорвало водопровод у Университета Кисии»), агент задаёт уточняющие вопросы (тип, локация, серьёзность, описание), собирает структурированный incident report, выдаёт reference number и кладёт в дашборд для county government / НГО / университета. Слоган: Speak → Understand → Decide → Take Action.

**2. Как использован AssemblyAI**

**В README про AssemblyAI нет ни единого слова.** Весь README — 1010 символов, и это инструкция по накатыванию миграций Supabase. Единственный технический след AssemblyAI в репозитории — npm-скрипт `"voice:test": "node scripts/assemblyai-stream-test.mjs"` и зависимость `ws@^8.21.3` в `dependencies`. Из этого следует, что используется **streaming STT через собственный WebSocket-клиент** (не Voice Agent API и не SDK — пакета `assemblyai` в `package.json` нет). Ни модель (Universal-3/3.5), ни turn detection, ни speaker labels, ни tool calling, ни LeMUR, ни LLM Gateway нигде не заявлены и не подтверждаются. Текст заявки утверждает «Powered by AssemblyAI's Voice Agent technology… listens to users in real time… asks intelligent follow-up questions» — **README не подтверждает этого ни на одну строку**. Более того, теги заявки перечисляют «GPT-3.5, AI21 Labs, AIML, AMD ROCm, AMD Developer Cloud» — то есть диалоговый слой, судя по заявке, вообще не AssemblyAI, а сторонний LLM.

**3. Архитектура и стек**

Next.js 16.3.4 + React 19.2.8, TypeScript 5, Tailwind 4 (`@tailwindcss/postcss`), Zod 4 для валидации, Supabase (Postgres) через `@supabase/ssr` + `@supabase/supabase-js`, деплой Vercel (`vercel.json`). Схема БД описана содержательно и это лучшая часть README: таблицы `incidents`, `incident_status_history`, `incident_updates`, «indexes for reference lookups, reporting time, status/category filtering, location similarity, and text search», смена статуса пишется автоматически «by a database trigger». Гигиена ключей проговорена правильно: «The server uses the service-role key only in route handlers; do not expose it as a `NEXT_PUBLIC_*` variable». Поток аудио **не описан нигде** — как микрофон попадает в AssemblyAI, кто держит WebSocket (браузер или Next.js route handler), как минтятся токены, есть ли вообще TTS-ответ — неизвестно. Название пакета `sauti-ai-ke-temp` («temp») намекает, что репозиторий поднят наспех.

**4. Настоящая инженерная суть**

Единственное, что здесь реально спроектировано — **модель данных инцидентов**: история статусов, апдейты, триггер на переход статуса, индексы под location similarity и full-text search. Это грамотный backend-дизайн для case management. Всё остальное не видно. Голосовой слой в репозитории не описан и, судя по составу зависимостей, тонкий: raw `ws` к streaming-эндпоинту. Диалоговая логика «умных доп-вопросов» — либо промпт к внешнему LLM, либо (что вероятнее при 8 коммитах) скриптованная последовательность слотов. Ничего из того, что делает голосового агента сложным — turn detection, barge-in, tool calling, латентность, аудио-ресемплинг, устойчивость к обрыву WebSocket — не заявлено и не задокументировано.

**8. Чем это можно побить**

Разрыв «популярность против инженерии» здесь и есть точка атаки, но бить в лоб («у них плохой README») бесполезно — судья и так это увидит. Бить надо **тем же социальным аргументом, но доказанным**:

Ход 1: если наша ниша хоть частично пересекается с гражданскими/доступностными сценариями — предъявить **многоязычность как измеренный факт**, а не как обещание: конкретные `language_codes`, code-switching и таблица точности на неанглийской речи. SAUTI позиционируется как доступность для суахилиязычных, но поддержки не показывает — зияющая дырка прямо в центре их истории.

Ход 2: предъявить **полный Voice Agent API loop с HTTP tools**, где агент сам пишет структурированный инцидент через tool call в БД во время разговора. У них структура собирается, судя по всему, постфактум, и агентности в AssemblyAI-смысле нет.

Ход 3: **документация как оружие.** Один README с архитектурной диаграммой, таблицей «фича AssemblyAI → файл», тестами и цифрами латентности по определению обходит их 1010 символов про Supabase-миграции по трём критериям из четырёх. Дешёвый и абсолютно надёжный дифференциатор против текущего лидера.
