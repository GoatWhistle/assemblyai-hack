# Aura · SEC EDGAR 10-K In-RAM Financial Voice Agent

**Тир:** B — Крепкие  
**Чем силён:** Лучшая архитектурная идея: PGlite (WASM Postgres) как детерминированный слой истины, --max-old-space-size=256

**1. Что построено**

Разговорный финансовый терминал: аналитик голосом спрашивает про показатели из аудированных отчётов SEC Form 10-K («Compare Amazon and Walmart operating margins», «What was Exxon Mobil's Free Cash Flow?») и получает произнесённый ответ. Ключевая идея — **детерминированная числовая точность**: цифры не генерируются моделью, а берутся SQL-запросом из предзагруженной в память базы. Данные 10-K лежат в WebAssembly-PostgreSQL (`PGlite`) в RAM, запросы выполняются «в `<1ms` с нулевым дисковым I/O».

**2. Как использован AssemblyAI**

Заявлено конкретно, но с внутренним противоречием между README и девпостом:

- README: «AssemblyAI **Universal-3.5 Voice Agent API** (WebSocket, **24kHz Linear PCM** streaming)», «real-time Voice Agent API (24kHz Linear PCM) with **hardware-level resampling and voice activity turn detection**».
- Devpost: «**AssemblyAI Universal-3.5 Realtime**… транскрибирует произнесённый запрос **менее чем за 200 миллисекунд** с высокой точностью на финансовой терминологии». Это другой продукт, чем Voice Agent API.
- В `.env` требуются **и `ASSEMBLYAI_API_KEY`, и `ASSEMBLYAI_AGENT_ID`** — наличие `AGENT_ID` подтверждает использование именно Voice Agent API со stored agent, а не просто стримингового STT. Это единственное машинно-проверяемое подтверждение, и оно в пользу Voice Agent API.
- Названы фичи: **voice activity turn detection**, «hardware-level resampling» на стороне браузера (Web Audio API, «real-time audio downsampling & visualization»).
- Экзотика: **«Caller Voice Isolation: Analyzes fundamental frequency ($F_0$) to maintain speaker focus during conversational turns»** — собственная эвристика изоляции голоса звонящего по основному тону. Небанальная идея, но это не фича AssemblyAI, а самодельный слой, и он никак не измерен.

Однако **reasoning отдан Google Gemini API / Groq**, а не AssemblyAI LLM Gateway. При том что `ASSEMBLYAI_AGENT_ID` подразумевает серверную LLM-оркестрацию внутри Voice Agent API, соседство с Gemini/Groq в стеке создаёт неясность: кто на самом деле ведёт диалог и вызывает инструменты. README этого не разрешает. Для судьи это значит: «Voice Agent API используется, но частично, а голову привели свою».

Ничего не сказано про speaker labels, formatting, **keyterms под финансовую лексику** (тикеры, «EBITDA», «capex», «FCF» — очевидные кандидаты), про barge-in, про tool-calling контракт. При заявке на «высокую точность на финансовой терминологии» отсутствие keyterms/prompt-biasing — недоработка ровно там, где она нужнее всего.

**3. Архитектура и стек**

Node.js в ESM (`"type": "module"`), Express 4.19.2, `ws` 8.17.0 (собственный WebSocket-слой), dotenv 16.4.5. БД — **`@electric-sql/pglite` 0.2.14**: Postgres, скомпилированный в WebAssembly, работающий в памяти процесса. Фронт — ванильный JavaScript + Web Audio API + CSS3, без фреймворка. Сервер запускается с **`node --max-old-space-size=256`** — автор сознательно ограничил heap 256 МБ, что для in-RAM базы «200+ S&P 500 SEC 10-K filings» является жёстким и осмысленным констрейнтом. Порт 5035. Деплой — Render. Всего 4 прод-зависимости — минималистично и приятно.

`top_level`: `server`, `public`, `tests`, `docs`, `.node-version`, `package.json`, `.env.example`. Чисто, без мусора.

Поток аудио: браузер захватывает микрофон, Web Audio API делает даунсэмплинг до 24 kHz Linear PCM, поток идёт по WebSocket. **Где заканчивается собственный `ws`-сервер и начинается соединение с AssemblyAI — из README не ясно** (мост на сервере или прямое подключение браузера). Для голосового проекта это существенный пробел, и он же тянет за собой вопрос о защите API-ключа.

**4. Настоящая инженерная суть**

Самая интересная техническая идея разобранных проектов:

- **PGlite как слой детерминированной истины.** Правильный архитектурный ответ на численные галлюцинации LLM: не «попроси модель посчитать аккуратно», а «выведи число из реляционного запроса и дай модели только озвучить». Формулировка автора точна: «Revenue, gross margin %, net income, and free cash flow metrics are queried via relational SQL rather than estimated probabilistically». По сути — тот же инвариант, что у RevenueFlow («модель решает что, система решает что можно»), но применённый к числам.
- **Отраслевая осведомлённость в расчётах** (из девпоста, в README её нет): стандартные gross/operating margin для tech и retail, но переключение на net revenue, net interest margin и андеррайтинговые метрики для банков и страховщиков. Редкое понимание того, почему «gross margin коммерческого банка» — бессмысленная величина. Профессиональные инструменты на этом ломаются постоянно, и автор это знает.
- **Работа с бюджетом памяти**: `--max-old-space-size=256` + WASM Postgres + 200+ файлингов — реальная оптимизационная задача, а не декларация.
- **Out-of-band аудит-трейл**: инструмент автоматически логирует запрошенные метрики в append-only файл `financial_notepad.txt` «without blocking the main event loop». Аудит-след для финансового инструмента — правильный инстинкт, хотя текстовый файл — слабое исполнение.
- **Мультитёрновые сравнительные запросы** через несколько компаний (Walmart против Microsoft) с удержанием контекста между ходами.
- **Изоляция голоса по $F_0$** — самодельный и небанальный ход.

Обёрткой является всё остальное: голосовой слой (Voice Agent API делает STT/TTS/turn detection), reasoning (Gemini/Groq). Своя работа — data layer и его дисциплина.

**5. Метрики и доказательства**

Заявлено больше, чем подтверждено, но структура доказательств есть:

- **`npm test` → `node tests/index.mjs`**, «**5-suite** PIET test suite». В README перечислены **4** пункта при заявленных 5 сьютах:
  1. «6-gate falsification and negative lookups»
  2. «Relational schema consistency across **200+ S&P 500 SEC 10-K filings**»
  3. «Multi-turn deep memory retention»
  4. «Ephemeral session teardown invariants»
  — то есть **5 заявлено, 4 показано**. Мелкая, но настоящая несогласованность. Аббревиатура «PIET» нигде не расшифрована.
- **`<1ms` на SQL-запрос** — правдоподобно для in-memory Postgres на предзагруженных данных, но **не измерено**: ни бенчмарка, ни метода, ни размера выборки.
- **«under 200 milliseconds»** на транскрипцию (девпост) — это цифра из маркетинга AssemblyAI, а не собственный замер. Ни лога, ни скрипта. Непроверяемо.
- **«Sub-second response times»** в первом абзаце README — ни одного замера полного голосового цикла (речь → ответное аудио). Для проекта, чей главный питч — скорость, отсутствие end-to-end замера критично.
- Точность: «deterministic numerical accuracy» — заявление архитектурное, а не измеренное. **Нет валидации извлечённых цифр против оригинальных файлингов**, нет golden set, нет отчёта «на N вопросах точность M%». А именно это — центральная претензия продукта.
- **11 коммитов** — минимум среди разобранных.
- Демо на Render (`onrender.com`) — вероятно, free plan с тем же 30–60-секундным пробуждением, что у VoiceMed, но здесь про это не предупреждают.

**Главное, за что стоит уважать**: раздел «Engineering Note» в конце README — *«This project is an exploratory technical prototype. Multi-turn context handling across diverse financial edge cases and voice activity detection thresholds under varying background acoustic environments require ongoing testing and refinement.»* Единственное среди разобранныхпрямое признание незрелости, подписанное автором. Против фальшивых «99.4% accuracy» у Veritas это выглядит достойно — но оно же даёт судье готовую цитату «сам автор называет это прототипом».

**6. Сильные стороны**

- **Самая изящная центральная идея.** Детерминированный слой истины под голосовым интерфейсом через in-RAM WASM Postgres — техническое решение, которое объясняется одним предложением и убедительно решает названную проблему (LLM путает фискальные годы и выдумывает метрики). По Originality это сильнее всех четырёх остальных.
- **Отраслевая корректность метрик** (банки/страховщики против tech/retail) — деталь, которую оценит любой судья с финансовым бэкграундом, и которой нет ни у одного конкурента в финансовой нише.
- **Чистая, минималистичная инженерия**: 4 прод-зависимости, ESM, явный лимит heap, ванильный фронт, папки `docs` и `tests`. `package.json` приятно читать.
- **README написан взрослым языком** — без эмодзи в заголовках, без «defense-grade», с чёткой структурой Overview → Capabilities → Stack → Getting Started → Tests → Engineering Note. По тону самый профессиональный документ разобранных проектов (при этом самый короткий из содержательных — 3292 символа).
- **Публичное демо** и **работающий `npm test`**.
- **`ASSEMBLYAI_AGENT_ID` в `.env`** — подтверждает реальное использование Voice Agent API со stored agent, что по «Application of Technology» ставит проект выше Veritas и SmartLink.
- Аудит-трейл запрошенных метрик — правильный инстинкт для финансового инструмента.

**7. Слабые места и уязвимости**

- **11 коммитов** — меньше всех. При заявленном объёме (парсинг 200+ файлингов, схема, голосовой слой, $F_0$-изоляция, 5 тест-сьютов) история работы не видна.
- **Ни одного собственного измерения.** `<1ms`, «sub-second», «under 200 ms» — все три числа либо теоретические, либо чужие. Ни лога, ни бенчмарк-скрипта, ни p50/p95. Для проекта, продающего скорость, это самая большая дыра.
- **Точность данных не валидирована.** Весь продукт стоит на утверждении «мы даём аудированные цифры без галлюцинаций», но нет ни одного доказательства, что цифры в PGlite совпадают с оригинальными 10-K. Достаточно одного вопроса «как вы проверили, что ваш парсер не перепутал фискальный год — то самое, за что вы критикуете чат-боты?», чтобы поставить всё под сомнение. Это ирония, лежащая в самом центре проекта.
- **5 сьютов заявлено, 4 перечислено. «PIET» не расшифровано.**
- **Противоречие в описании AssemblyAI**: README говорит «Voice Agent API», девпост — «Universal-3.5 Realtime» (другой продукт). Плюс `GEMINI_API_KEY` в обязательных переменных при наличии `ASSEMBLYAI_AGENT_ID` — судья справедливо спросит, какой именно LLM ведёт диалог и вызывает инструменты. Ответ «оба» ослабляет и техническую ясность, и нарратив «сделано на AssemblyAI».
- **Нет keyterms / transcription_prompt под финансовую лексику**, при том что весь домен — это тикеры, аббревиатуры (EBITDA, capex, FCF) и названия компаний, то есть именно тот случай, для которого biasing существует. VoiceMed это сделал, Aura — нет. Прямое сравнение не в её пользу.
- **Поток аудио описан не до конца**: где живёт WebSocket-соединение с AssemblyAI, как защищён API-ключ (нет упоминания token minting — в отличие от VoiceMed с одноразовыми токенами и 2-минутным окном). Если браузер коннектится напрямую с ключом — это утечка ключа.
- **Финансовая ответственность**: продукт озвучивает финансовые показатели для принятия решений, и **дисклеймера «not financial advice» нет**. При заявлении «deterministic numerical accuracy» и ошибке парсинга — прямая репутационная и юридическая поверхность. Veritas тоже без дисклеймера, VoiceMed с ним; Aura здесь на стороне проигравших.
- **Presentation — слабое место.** README без скриншотов, без архитектурной диаграммы, без демо-скрипта, без видео. 3292 символа. `docs/` есть, но её содержимое неизвестно. Рядом с Veritas и VoiceMed это выглядит бедно, при том что идея внутри лучше.
- **«Caller Voice Isolation» по $F_0$** — заявлено, не измерено, и сам автор в Engineering Note признаёт, что пороги VAD в разных акустических условиях требуют доработки. Фича заявлена как capability и тут же дисквалифицирована в примечании к тому же документу.
- **Свежесть данных не обсуждается**: 10-K выходят раз в год, но предзагруженный снапшот в RAM означает, что данные устаревают молча. Ни слова о том, как обновляется база и что видит пользователь, спросив про только что вышедший отчёт.
- **Пересечение с SmartLink** по паттерну «голос → SQL → аналитика», хотя домены разные (финансы против рекламы). Если судьи группируют, обе попадают в «voice-to-database query».

**8. Чем это можно побить**

Aura опасна идеей, а не исполнением. Атака должна признать идею и обойти исполнение:

1. **Обратить их центральное обещание против них — валидацией данных.** Они обещают «deterministic numerical accuracy» и не проверяют собственный парсер. Наш ход: **опубликовать валидационный отчёт** — N запросов против источника истины, точность с числом, и скрипт, который это прогоняет (`npm run validate`). Таблица «100 запросов, 100 совпадений с первоисточником, вот лог» делает их «deterministic» голым прилагательным. Формулировка для судьи: «мы тоже детерминированы, но мы это измерили».
2. **Забрать латентность, которую они заявляют и не измеряют.** Их «sub-second» и «<200 ms» — чужие числа. Наш ход — измеренный end-to-end голосовой цикл с p50/p95 и воспроизводимым скриптом. Плюс `keyterms` под доменную лексику, которых у них нет: это даёт и лучшую точность на терминах, и аргумент «мы использовали фичу AssemblyAI, специально сделанную для этой задачи, а они — нет».
3. **Снять их неоднозначность в стеке и выиграть по «Application of Technology».** У них `ASSEMBLYAI_AGENT_ID` рядом с `GEMINI_API_KEY`, и непонятно, кто ведёт диалог. У нас должно быть однозначно: **Voice Agent API держит весь цикл** (STT + LLM-оркестрация + TTS + turn detection + tool calling), и это нарисовано одной диаграммой. На спонсорском хакатоне «один провайдер, один ключ, весь голосовой рантайм» — выигрышный нарратив, который RevenueFlow нащупал в тексте, но не довёл до Voice Agent API, а Aura довела до Agent ID, но размыла Gemini.
4. **Взять их приём с аудит-трейлом и сделать его правильно.** Их append-only лог метрик в `financial_notepad.txt` — правильная идея в слабом исполнении. У нас: структурированный аудит каждого вызова инструмента (что спросили, какой инструмент, какие аргументы, какой результат, из какого источника, с какой временной меткой), видимый в UI как таймлайн и выгружаемый. Это одновременно доверие и демонстрация tool calling судье в реальном времени.
5. **Presentation, где они беззащитны.** 3292 символа без единой картинки при лучшей идее среди разобранных. Скриншоты, диаграмма потока аудио, 90-секундное видео с живым звуком и 60-секундный демо-скрипт (приём VoiceMed) — и по Presentation мы впереди, не тронув код.
6. **Поставить дисклеймер, которого у них нет.** «Not financial advice», раздел про свежесть данных и явное «что делает система, когда не знает ответа». Это стоит один абзац и закрывает вопрос, на котором Aura споткнётся.
