## Главный вывод по технологии

Критерий «Application of Technology» — про то, насколько глубоко задействован стек AssemblyAI. И здесь поле ведёт себя предсказуемо: 25 из 45 проектов берут Voice Agent API, подключаются одним WebSocket, получают готовый разговор и на этом останавливаются. Это ровно то, что API делает из коробки, — то есть за это нельзя получить высокий балл, потому что заслуга здесь API, а не команды.

Зато три возможности почти никем не тронуты, и каждая даёт объективное, проверяемое преимущество:

### 1. Word-level timings — 2 проекта из 45
Тайминги на уровне слов позволяют привязать каждое утверждение агента к точной секунде в аудио. Это превращает «агент так сказал» в «вот доказательство, вот 00:04:17.3». Voice Action Gate и Brand Studio Agent это нащупали: первый не даёт агенту выполнить необратимое действие, если аргумент нельзя вывести из реально произнесённых слов, второй цитирует конкретную провалившую строку. Оба — среди самых умных идей на хакатоне, и оба используют одну и ту же механику, которую остальные 43 проекта проигнорировали.

### 2. Speaker labels / диаризация — 3 проекта
Почти все делают агента «один на один с пользователем». Но самые ценные корпоративные сценарии — там, где в комнате два и более человека, и важно кто именно что сказал: продавец или клиент, врач или пациент, следователь или свидетель. Saakshi построил на этом весь продукт (кто из двоих произнёс запрещённое обещание — определяет, есть ли нарушение). Это даёт бизнес-ценность, которую невозможно получить без диаризации.

### 3. LeMUR — 2 проекта
Модель для анализа уже собранного разговора (пост-обработка, суммаризация, извлечение по своей схеме). Использовали только Uh-Huh и EverCall. Комбинация «realtime STT в разговоре + LeMUR для разбора после» закрывает полный цикл и показывает знание продукта AssemblyAI за пределами одного эндпоинта.

### 4. Мультиязычность и code-switching — 4 проекта
Universal-3 распознаёт смешанную речь внутри одного предложения. Saakshi эксплуатирует именно это (English + Hindi в одной фразе — Hinglish), и это ровно тот случай, где ни одно конкурирующее решение на Whisper не даст того же результата. Для судей из AssemblyAI это прямая демонстрация преимущества их модели.

## Что это значит для нашего проекта

Формула отрыва по «Application of Technology» складывается из трёх слоёв:

1. **Не только Voice Agent API.** Брать streaming STT напрямую там, где нужен контроль (тайминги, диаризация, свои пороги), и Voice Agent API там, где нужна скорость разговора. Гибрид сразу отличает от 25 однотипных проектов.
2. **Использовать редкие фичи как несущую конструкцию, а не украшение.** Word timings + speaker labels должны быть тем, без чего продукт не работает вообще, а не галочкой в README.
3. **Замерять и показывать числа.** Латентность p50/p95, точность на своём тестовом наборе, число ложных срабатываний. Поле почти не приводит измерений, а судьи-инженеры из Amex, Prudential, Zocdoc и Meta читают именно цифры.
